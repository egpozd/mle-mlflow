# Улучшение baseline-модели

Учебный проект посвящён прогнозированию стоимости недвижимости и продолжает работу предыдущего спринта по подготовке данных и обучению CatBoostRegressor. Основная метрика — RMSE. В проекте исследовано влияние генерации и отбора
признаков, а также настройки гиперпараметров. Результаты экспериментов и версии моделей сохранены в MLflow.

## Особенности выполнения проекта

В связи с проблемами доступности учебной облачной инфраструктуры Яндекс Практикума проект был выполнен в локальном окружении. Вместо учебной виртуальной машины использовались Docker Desktop, локально развёрнутые PostgreSQL и
MLflow Tracking Server. Артефакты экспериментов сохранялись в локальном файловом хранилище. Это позволило выполнить все этапы, провести эксперименты и зарегистрировать модели в MLflow Model Registry. Yandex Object Storage (S3)
фактически не использовалось.

## Используемые технологии

Python 3.10, pandas, scikit-learn, CatBoost, autofeat, mlxtend, Optuna, MLflow 2.7.1, PostgreSQL, Docker Desktop и Jupyter Notebook. Для визуализаций использованы Matplotlib и Seaborn.

## Этапы работы

1. **Этап 1 — Базовая модель.** Исходная CatBoost-модель восстановлена на основе результатов предыдущего спринта, проверена по историческим данным и метрикам и зарегистрирована как V1. Метаданные происхождения сохранены в
   `model_improvement/baseline/`.
   Для регистрации использовалась команда `.\.venv\Scripts\python.exe -B mlflow_server/register_baseline.py`; она также проверяет модель на исторической тестовой выборке и не нужна для просмотра готовых результатов.
   [Shell-скрипт запуска MLflow](mlflow_server/run_server.sh) предусмотрен для S3-конфигурации; локальный скрипт запуска на PowerShell приведён ниже.
2. **Этап 2 — Исследовательский анализ данных (EDA).** Исследованы распределения цены и признаков, корреляции, зависимости, выбросы и возможные факторы стоимости. Выводы сохранены в ноутбуке Jupyter, отдельном [Markdown-отчёте](model_improvement/eda_conclusions.md) и
   MLflow.
3. **Этап 3 — Генерация признаков.** Проверены предметные признаки, `PolynomialFeatures`, `KBinsDiscretizer` и `autofeat`. Преобразования объединены через `ColumnTransformer` и `sklearn.Pipeline`. Для продолжения выбрана
   конфигурация F2: 14 исходных признаков, 6 попарных взаимодействий `total_area`, `rooms`, `floors_total`, `build_year` и 4 признака дискретизации площадей `total_area`, `living_area`, `kitchen_area` и высоты потолков `ceiling_height`.
   Всего получено 24 признака; модель зарегистрирована как V2. На исторической тестовой выборке генерация признаков не улучшила RMSE относительно V1.
4. **Этап 4 — Отбор признаков.** Выполнены последовательный прямой отбор (SFS) и последовательный обратный отбор (SBS) из `mlxtend`. Выбрана конфигурация с восемью признаками, зарегистрирована V3.
   Сокращение набора не улучшило RMSE на тестовой выборке: результат V3 хуже V2 и исходной V1.
5. **Этап 5 — Подбор гиперпараметров.** Сравнены `RandomizedSearchCV` и Optuna с `TPESampler` и `MLflowCallback`. По групповой кросс-валидации выбрана конфигурация RandomizedSearchCV. Итоговый пайплайн зарегистрирован как V4.
   Настройка снизила RMSE на тестовой выборке относительно V3, но не позволила превзойти V1.

### Основные выводы EDA

- У цены выражен правый хвост: среднее — 18,52 млн руб., медиана — 11,85 млн руб. На объекты выше P99 приходится 73,81% суммы квадратов отклонений цены от среднего; это вклад в разброс целевой переменной, а не в ошибки модели.
- Цена положительно связана с общей площадью: коэффициент корреляции Пирсона — 0,783, коэффициент корреляции Спирмена — 0,764.
- Медиана цены различается по этажным группам: первый этаж — 9,90 млн руб., промежуточные — 12,00 млн руб., последний — 11,50 млн руб. Различия не доказывают причинного влияния этажа.

## Результаты

Оценка на исторической тестовой выборке:

| Версия | Этап | RMSE, руб. | MAE, руб. | R² |
|---|---|---:|---:|---:|
| V1 | Базовая модель | 10 547 270,06 | 3 744 622,81 | 0,894899 |
| V2 | Генерация признаков | 10 594 103,15 | 3 749 084,73 | 0,893964 |
| V3 | Отбор признаков | 11 811 402,85 | 3 795 846,93 | 0,868196 |
| V4 | Подбор гиперпараметров | 10 995 267,83 | 3 533 863,89 | 0,885782 |

По основной метрике RMSE лучший результат сохранился у V1. Настройка гиперпараметров снизила RMSE относительно V3, а V4 получила минимальную MAE среди четырёх моделей. Улучшить базовую модель по RMSE не удалось: усложнение
обработки признаков не всегда повышает качество прогнозирования.

## Локальный запуск

Клонирование репозитория и переход в каталог проекта:

```powershell
git clone https://github.com/egpozd/mle-mlflow.git
cd mle-mlflow
```

Команды ниже рассчитаны на настроенное Windows-окружение с PowerShell, Docker Desktop, Python 3.10 и виртуальным окружением `.venv` в корне репозитория. Версии зависимостей указаны в `requirements.txt`:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Docker Compose находится **вне репозитория**, в `..\mle-local-infra` (в текущем окружении — `C:\Users\egpoz\mle-local-infra`). Для запуска нужны этот каталог с конфигурацией и подготовленные БД и пользователь `mlflow`. Настройки
подключения задаются в локальном `.env` по образцу `.env_template`; секреты в Git не включены.

Если PostgreSQL и MLflow ещё не запущены, из корня репозитория:

```powershell
docker compose -f ..\mle-local-infra\docker-compose.yml up -d postgres
.\mlflow_server\run_server_local.ps1
```

PostgreSQL доступен на `127.0.0.1:5433`. Команда Compose запускает сервер БД, но не восстанавливает историю экспериментов. Скрипт запуска MLflow работает в текущем терминале и явно выбирает локальное хранение.

В другом терминале можно проверить сервер и открыть ноутбук Jupyter:

```powershell
Invoke-RestMethod http://127.0.0.1:5000/health
Start-Process 'http://127.0.0.1:5000'
.\.venv\Scripts\python.exe -m jupyterlab model_improvement/model_improvement.ipynb
```

Интерфейс MLflow: [http://127.0.0.1:5000](http://127.0.0.1:5000).

Для повторного выполнения нужны файлы обучающей и тестовой выборок `train.csv` и `test.csv` из предыдущего спринта, расположенные в `..\mle-baseline-recovery\data`. В обучающей выборке 112 734 строки, в тестовой — 28 184. CSV не входят в Git; их происхождение и
контрольные суммы описаны в метаданных базовой модели. Путь к обучающей выборке для EDA задаётся в начале ноутбука Jupyter.

Каталоги `mle-local-infra`, `mle-baseline-recovery` и `mle-mlflow-runtime` не создаются одним клонированием этого репозитория. Для повторного выполнения части ячеек нужны сохранённые вспомогательные файлы JSON или их восстановление из MLflow. В
частности, на этапе 5 используются `reports/results.json` и `design/winner_before_C.json`, восстановленные как `results.json` и `winner_before_C.json` в `..\mle-mlflow-runtime\stage5` либо в каталоге `STAGE5_RUNTIME_DIR`.

Готовые таблицы, графики и выводы доступны в сохранённых результатах выполнения ячеек [основного notebook](model_improvement/model_improvement.ipynb) без повторного обучения. Полные эксперименты этапов 3–5 запускаются отдельными модулями этапов с флагом `--run`;
обычное чтение сохранённых результатов их не повторяет.

## MLflow

- Имя эксперимента: `real_estate_model_improvement`.
- Локальный идентификатор эксперимента: `1`. Он относится к этому экземпляру PostgreSQL/MLflow и может отличаться в другом окружении.
- Зарегистрированная модель: `real_estate_price_model`.
- Зарегистрированные версии: `1`, `2`, `3`, `4`, статус `READY`.
- Итоговая модель этапа 5: `models:/real_estate_price_model/4`.
- Идентификатор итогового запуска этапа 5: `52b6764852554b4eb42d49cc5106430a`.

Основные запуски экспериментов в MLflow:

| Этап | Названия запусков |
|---|---|
| Этап 1 | `reconstructed_baseline_v1` |
| Этап 2 | `stage2_eda` |
| Этап 3 | `stage3_baseline_grouped`, `stage3_manual_features`, `stage3_sklearn_features`, `stage3_autofeat`, `stage3_feature_generation` |
| Этап 4 | `stage4_feature_screening`, `stage4_sfs`, `stage4_sbs`, `stage4_feature_selection` |
| Этап 5 | `stage5_baseline_grouped`, `stage5_randomized_search`, `stage5_optuna`, `stage5_hyperparameter_tuning` |

В MLflow сохранены параметры, метрики, код, модели, окружения, сигнатуры моделей и отчёты соответствующих этапов.

Артефакты находятся в `..\mle-mlflow-runtime\artifacts`, история экспериментов и реестр моделей — в локальной PostgreSQL. Модели, артефакты и база данных не хранятся в GitHub. Для работы с текущими URI `file://` нужен доступ к тому же локальному
хранилищу артефактов.

В конфигурации предусмотрен скрипт запуска в режиме S3 `mlflow_server/run_server.sh`, но эксперименты проекта выполнены с файловым хранилищем. Сохранённые ноутбуки Jupyter и отчёты в MLflow являются снимками этапов; сообщения о статусе логирования или
регистрации внутри ранних снимков относятся к моменту их сохранения.

## Ограничения результатов

В данных встречаются повторяющиеся комбинации характеристик, но это не доказывает, что записи всегда относятся к одному объекту. Для внутренних оценок применялась групповая валидация. Тестовая выборка имеет известные пересечения
с обучающей по характеристикам и уже использовалась в истории разработки. Полученные метрики нельзя считать строгой независимой оценкой качества на совершенно новых объектах.
Кросс-валидация пятого этапа оценивает модель с фиксированным набором признаков, ранее отобранным на выборке для разработки модели, а не всю процедуру отбора и настройки.
